# 持续运行的智能体

所有 Agent 入口共用 ReAct 执行引擎：根据目标安排步骤、调用工具、读取实际结果、调整计划并验证完成情况。Agent 不再因为固定轮次、调用总数或固定总时长而结束任务。旧的 `max_tool_rounds`、`max_total_tool_calls` 配置保留兼容读取，已不参与新引擎的停止判断。

## 使用方式

- Web 对话提交后在后台执行，关闭页面不会取消任务。重新打开对话可查看状态，短暂断线后按事件序号恢复订阅。
- 组织工作台的“执行任务”可以统一查看网页、消息渠道、定时任务和工作流的任务，处理审批、补充输入、恢复或停止任务。
- 私聊支持 `/task` 查看当前会话任务、`/stop` 停止、`/resume 补充要求` 恢复。任务等待输入时，下一条普通回复会交回原任务。
- 脚本要求验证码等输入时，原任务保留等待现场，回复直接续跑脚本，再由 Agent 检查后续结果；输入值不会写入 Agent 上下文。输入声明和续跑关联会持久化，过期输入需重新发起脚本，结果不确定的续跑不会自动重复提交。
- 定时任务使用独立上下文，完成或需要处理时发送通知。审批不会与普通私聊任务混用。
- 工作流 Agent 节点使用同一引擎。审批或输入同时出现在工作流待办中，工作流的总时限、取消指令仍然有效。未允许副作用的试运行只展示预览。

## 自动执行授权

原有权限和强制审批规则继续生效。组织管理员可以在 Agent 编辑界面选择哪些已绑定工具允许自动执行。自动执行授权不会授予新的工具、数据源或工作区访问权限。

Agent 配置新增：

```json
{
  "context_window_tokens": 32768,
  "automatic_tools": {
    "write_text_file": [{"path": "report.txt", "mode": "create"}],
    "run_command": [{"profile": "python"}]
  }
}
```

匹配规则是精确的参数匹配，多个对象代表多个可选范围；`[{}]` 表示该工具在既有权限内自动执行全部操作。空对象之外的规则必须包含所有指定参数并匹配其值。组织强制审批、插件 `approval_policy=required` 和显式强制审批的工具不会被自动授权覆盖。

上下文容量应与所选模型一致。引擎保守估算消息和工具描述的大小，预留模型输出空间；长任务整理已结束步骤，完整工具结果仍保存在执行记录中。容量不足时暂停并说明原因。

## 状态和恢复

状态包括 `queued`、`running`、`waiting_approval`、`waiting_input`、`paused`、`succeeded`、`failed`、`cancelled`。正在执行且无法中断的操作收到停止指令后显示“正在停止”，结束后不再执行下一步。命令工具支持协作取消，仍保留各工具自己的超时、输出和工作区限制。

工具连续重复相同操作和结果三次时会触发重新规划；调整后继续重复则暂停。正常等待后台脚本的轮询会退让调度。模型临时故障沿用有限重试，任务费用继续统计和告警。

工具执行前登记步骤、执行后登记结果。服务重启后，未完成任务在原租约到期后恢复，已记录结果的步骤不会重复执行。若执行中崩溃且无法确认操作是否生效，任务暂停，由管理员在“执行任务”核对实际结果后继续。

## 接口

所有接口均要求登录，并校验组织及会话权限；处理任务需由发起人或管理员执行，核对不确定步骤需管理员权限。

| 接口 | 用途 |
|---|---|
| `POST /api/agent-runs` | 使用现有聊天请求格式创建后台任务，返回 202 |
| `GET /api/agent-runs?conversation_id=...` | 当前对话的任务 |
| `GET /api/agent-runs?organization_id=...` | 当前组织的任务 |
| `GET /api/agent-runs/{id}` | 任务状态和待处理事项 |
| `GET /api/agent-runs/{id}/events?after=...` | SSE 事件订阅；也支持 `Last-Event-ID` |
| `POST /api/agent-runs/{id}/cancel` | 停止任务及子任务 |
| `POST /api/agent-runs/{id}/resume` | 以 `user_input` 补充信息并恢复 |
| `POST /api/agent-runs/{id}/approvals` | 提交 `approval_id` 和 `approved`；审批只能使用一次 |
| `POST /api/agent-runs/{id}/reconcile` | 管理员提交 `step_key`、`ok` 及实际 `data` 或 `error` |

`/api/chat` 保留原请求格式及 token、done、工具和协作事件，增加任务状态、审批和输入事件。`done.run_id` 用于原有模型分析，`agent_run_id` 用于后台任务操作。

## 升级和部署

新增 SQLite 表通过幂等补丁创建，不修改现有聊天记录。部署前备份数据库，完成或取消升级前仍在内存中的任务与审批，再完整停止旧进程并启动新进程。旧内存现场无法自动转换为新任务。运行中的代码和配置不会通过文件修改自动生效。

没有可信租户身份的 `generate()` 调用继续只生成文本。多智能体只会委派给当前选择且已获组织授权的 Agent，按依赖传递结果；必要子任务失败时重新规划，仍不能完成则暂停，不会将部分结果记为任务成功。
